## Design Specificity Verdict

**LLM assessment**: Not specific. The accent is Tailwind's default fuchsia-purple palette. `--font-sans: "Inter"` is declared but never imported via `next/font` — the entire app renders in `system-ui`. Category icons are emoji in one place and Lucide icons in another. The only localized touch is M-Pesa as the default payment gateway. A wedding-venue marketplace in Tallinn could ship this unchanged.

**Deterministic scan**: 2 findings, both warnings. 1 gray-on-color (false positive — hover-only pairing), 1 overused-font (Inter in a print stylesheet). The source-mode detector under-reports here because it cannot evaluate computed contrast, layout, accessibility, or DOM behavior.

## Overall Impression

A structurally competent shadcn-class scaffold with no voice. It can be shipped, but it cannot yet be remembered. The product is named "Eventora" in the folder and "Eventicate" in every UI surface, the font declared is never loaded, and a Kenyan funeral booking lands on the same festive purple gradient as a corporate mixer. The single biggest opportunity: give this product an identity that earns its pan-African event marketplace position.

## What's Working

1. **Grouped cart by provider** (`cart/page.tsx`): Correct IA for a multi-provider marketplace. Per-provider subtotal + grand total + a single "Generate Quote(s)" CTA that pluralizes itself. The one place the UI thinks about the actual shape of the transaction.

2. **Subscription banner state matrix** (`provider/page.tsx`): Four distinct visual treatments for no-sub/trial/trial-expired/active, each with its own icon, color, copy, and CTA verb. The system knows where the user is in the billing lifecycle.

3. **Autocomplete keyboard model** (`Autocomplete.tsx`): ArrowUp/Down/Enter/Escape all behave, focusIndex tracks, click-outside listener. The most production-ready component in the codebase — which makes the missing ARIA roles genuinely tragic.

## Priority Issues

### [P0] Brand identity crisis & missing font
Project folder says "Eventora", every UI surface says "Eventicate", and `--font-sans: "Inter"` is declared in globals.css but never imported via `next/font`. The entire app renders in `system-ui` — the most generic fallback on the web.
**Why it matters**: Trust breaks before the user reads a word. A marketplace for African events that looks like every other SaaS starter has no reason to be chosen.
**Fix**: Pick one name and unify it. Wire `next/font/google` to load Inter (or a typeface that does product work for this market). Replace all hardcoded "Eventicate" strings in metadata, logo, footer, auth copy, and how-it-works.
**Suggested command**: `/impeccable typeset`, `/impeccable document`

### [P0] Two competing booking pipelines
`/providers/[id]` offers "Add to Cart" per service AND a top-level "Request Quotation" button. "Generate Quote(s)" on the cart ≠ "Request Quotation" (which routes to `/dashboard/bookings/new`). Same noun, two entirely different pipelines.
**Why it matters**: Users have no way to know they're different. The funnel forks silently and abandonment risk doubles.
**Fix**: Pick one canonical path. Show the other as secondary, or remove it. Rename "quotation" to "Get a quote" → "Lock the date" → "Pay your deposit" for consumer clarity.
**Suggested command**: `/impeccable shape`, `/impeccable clarify`

### [P1] Accessibility debt on the most polished component
`Autocomplete.tsx` implements a full combobox in DOM but with no `role="combobox"`, no `aria-expanded`, no `aria-controls`, no `role="listbox"`/`role="option"`, no `aria-activedescendant`. Payment modal has no `role="dialog"`, no focus trap, no Escape handler. Sidebar links have no `focus-visible` styling. Icon-only buttons (trash, +/-) have no `aria-label`. `Input.tsx` doesn't set `aria-invalid` when errored.
**Why it matters**: Screen-reader and keyboard users are locked out of the platform's most basic flows.
**Fix**: Add ARIA roles to Autocomplete, dialog semantics to modals, focus-visible to all links/buttons, aria-labels to all icon-only controls, and aria-invalid/describedby to errored inputs.
**Suggested command**: `/impeccable audit`, `/impeccable harden`

### [P1] Mobile navigation does not exist
Public header renders nav as `hidden md:flex` — on mobile the top bar shows only a logo with no way to reach Find Services, How It Works, or Sign In. Dashboard Sidebar is a fixed `w-64` aside with no toggle, no drawer, no bottom nav. On <768px the sidebar eats a third of the viewport.
**Why it matters**: This is a pan-African product where mobile-only users are the majority, not the exception.
**Fix**: Add a mobile hamburger/drawer for the dashboard sidebar and a bottom-nav or collapsible menu for the public header.
**Suggested command**: `/impeccable adapt`

### [P1] Funeral/church tone-deafness
Event types include FUNERAL and CHURCH — solemn, culturally loaded occasions — yet a shared festive purple gradient covers every hero. A bereaved family booking funeral transport lands on the same hero as a wedding planner.
**Why it matters**: Deep cultural miss for a pan-African product. The platform is tonally illiterate to its own event taxonomy.
**Fix**: Adapt palette/copy by event type. Funerals deserve a quieter hero, somber palette, and copy that doesn't say "Plan Your Perfect Event".
**Suggested command**: `/impeccable shape`, `/impeccable colorize`

### [P2] Subscription multi-select is conceptually broken
`selectedPlanIds: string[]` lets users check multiple plans and shows a "N plans selected / Total:" bar. But the action button calls `handleSubscribeClick(plans.find((p) => p.id === selectedPlanIds[0])!)` — silently discarding all but the first. A subscription is single-select; the entire surface is a UX bug dressed as a feature.
**Why it matters**: Users who check multiple plans get a misleading total and lose their selections.
**Fix**: Remove multi-select. Use radio-button behavior for plan selection.
**Suggested command**: `/impeccable clarify`

### [P2] Provider sidebar is 11 ungrouped items
Navigation is a flat list of 11 items with no grouping, no separators, no "create" affordance. Power providers managing 50 SKUs have to toggle each individually with no batch actions. No keyboard shortcuts, no command palette, no saved filters.
**Why it matters**: The primary user (provider-first product) is stuck in a recall-taxonomy navigation that punishes scale.
**Fix**: Group into 4-5 primary sections (Bookings, Inventory, Business, Account). Add a queue surface for pending actions as the dashboard home.
**Suggested command**: `/impeccable layout`, `/impeccable distill`

## Persona Red Flags

**Alex (Power User Provider — manages 40+ services)**: Every toggle is an individual fetch with no batch action. Cannot "deactivate all weekend services" without 40 clicks. No "duplicate service" affordance. Delete prompt is `confirm("Delete this service?")` — a 1995 dialog with no Undo, no archive, no existing-bookings check. Provider dashboard "Recent Bookings" shows last 10 with no filter, no "needs response" queue. 11-item flat sidebar requires memorizing that "Local Sync" lives between "Reviews" and "Subscription".

**Jordan (First-Time Customer booking a wedding)**: "Dynamic Pricing" card shows `Wedding ×1.5` and `+15% Peak Season` — the platform is teaching Jordan its pricing engine instead of telling Jordan the price. Availability calendar's `onMonthChange` is a no-op — Jordan can't see if her wedding date is free next year. No forgot-password link — Jordan mistypes her password, sees no recovery path, abandons. "Generate Quote(s)" — Jordan has never heard "quotation" outside B2B procurement. Expected "Checkout".

**Casey (Mobile-Only User — Android, M-Pesa primary)**: Public header nav is `hidden` on mobile — Casey can't reach `/search` from the homepage on her phone. Dashboard sidebar is `w-64` fixed — content column shrinks to half-screen; tables need horizontal scroll on 360px. Payment modal is `max-w-md` with no max-height or scroll — "Pay Now" button can push below the fold on small phones with no Escape handler. Cart row crams 6 horizontal children (image + name + price + qty + subtotal + delete) into ~330px. Every search keystroke triggers a fetch with no debounce — Casey on 3G pays for every letter.

## Minor Observations

- Review average in `providers/[id]/page.tsx` computed with `a! + b!` non-null assertions — divides 0/0 → NaN → StarRating renders "NaN". Provider model already exposes `averageRating` — use it.
- `StarRating` has no `aria-label` — screen readers announce "★ ★ ★ ★ ★ 4.2" instead of "4.2 out of 5 stars".
- Search reads `?category=` from URL on mount but doesn't write back when filters change — shareability and back-button lose.
- `h-15 w-20` class in EquipmentActions/ServiceActions — 3.75rem, not part of documented Tailwind scale; thumbnails at 60-80px too small.
- "Clear Cart" is `variant="outline"` — a destructive bulk action should be danger-styled with confirm.
- `getSavingsPct` synthesizes 15% annual discount when annualPrice is null — UI advertises "Save 15%" from missing data.
- ServiceActions and EquipmentActions define identical inline `ToggleSwitch` — should be `components/ui/Toggle.tsx`.
- `Input.tsx` derives `id` from label — two inputs with the same label share one id. Use React `useId()`.
- Pending-actions banner uses one AlertCircle icon for two distinct concerns (payments vs agreements).
- `AuthForm.tsx` has `phone` in form state but never renders it.
- `how-it-works/page.tsx` duplicates the 4-step model from the homepage with only slightly longer copy.
- `EventicateLogo` fetches `/api/admin/logos` on every page load — wasteful for non-admins who always get 403.
- `Inter` in `DocumentPrintStyles.tsx` flagged by detector — acceptable in print stylesheet context.

## Questions to Consider

1. If the brand palette were derived from kente/kitenge/Ndebele pattern palettes instead of Tailwind's fuchsia default, which surfaces would still need to be quieter? Could event-type control the palette?

2. Why does the customer see "Dynamic Pricing" modifiers at all? Hotels show you the price, not "×1.5 because it's a weekend." Could disclosure move to a "Why this price?" tooltip?

3. Is "quotation" the right verb for a consumer marketplace? If the flow were renamed "Get a quote" → "Lock the date" → "Pay your deposit", would the cart-vs-booking dual-pipeline dissolve into a single linear funnel?

4. What if the provider dashboard were a *queue* (pending requests waiting on them) instead of a stat-card grid? Power users don't need 11 equal-weight buttons — they need their next-action served first.

5. M-Pesa is the only localized touch. What if you built ten more — currency picker respecting KES/NGN/GHS, DD/MM date defaults, M-Pesa till number verification, "share booking via WhatsApp" — and let the marketing page stay quiet?

6. What does "Eventicate / Eventora" mean? If you had to express the brand promise in one East African phrase — harambee, ubuntu, pamoja — which surfaces would change first?
