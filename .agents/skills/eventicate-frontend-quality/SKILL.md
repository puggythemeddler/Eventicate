# Eventicate frontend quality

Use with `eventicate-product` when changing public pages, organizer/provider dashboards, admin screens, forms, or attendee ticket flows. Treat interface quality as a complete user journey: product fit, visual hierarchy, content, interaction, accessibility, mobile behavior, and implementation performance.

## Combine skills by responsibility

1. **Product truth:** use `eventicate-product` for roles, East African market context, currencies, ticketing boundaries, and the current design system.
2. **Visual direction and craft:** use Impeccable as the lead for the requested surface. Keep the existing identity for refinements; choose a replacement direction only when the user asks for a redesign.
3. **Distinctiveness:** use design-taste-frontend to avoid generic layouts and select a coherent visual direction. Do not let it override the established product or a clear design brief.
4. **UX, accessibility, and responsive behavior:** use UI/UX Pro Max for focused checks on the affected interface, such as mobile forms, touch targets, keyboard access, readable contrast, or navigation.
5. **React and Next.js implementation:** use Vercel React best practices for component structure, rendering, and performance; use ECC React/TypeScript patterns where they add relevant implementation guidance.

Do not load every reference skill for a narrow change. Select the skills that cover the actual surface and concern, then reconcile overlap into one set of recommendations before editing.

## Eventicate interface checks

- Design mobile-first for organizers, providers, and attendees; keep core tasks usable on slower connections and smaller screens.
- Keep price, currency, location, date/time zone, availability, and fee responsibility clear where users make decisions.
- Keep private event planning and public ticket discovery distinct while making the shared organizer workspace understandable.
- Preserve plain, locally understandable copy and avoid implying that every country has the same payments, currency, language, or rules.
- Check loading, empty, validation, success, and error states, as well as keyboard and touch interactions.
- Use real product data and organizer-provided imagery. Do not invent testimonials, providers, or event claims.
- When UI changes are requested, inspect the rendered experience at desktop and phone sizes and address visible issues before delivery.
